Ansible facts

Every fact the setup module can return on Linux, Unix and Windows hosts, with its type, meaning, the gather_subset and platforms that collect it, and where its value comes from. Extracted from the source code of the ansible-core fact collectors and of the ansible.windows setup module.

How to read this reference
  • Facts are named as keys of ansible_facts (ansible_facts['distribution']). Below each name is the legacy top-level variable (ansible_distribution).
  • Names in <angle brackets> are runtime keys: one entry per interface, device, mount… [] stands for the elements of a list.
  • A type such as str | null lists every type the code can assign, on any platform.
  • auto marks descriptions derived from the fact name rather than written by hand.
  • Source shows where a value is read from (files, commands, Python APIs, registry keys, WMI classes, .NET APIs) and links to the lines that set it.
  • Windows hosts run ansible.windows.setup, a separate PowerShell module, using the latest ansible.windows release that supports this ansible-core version. Where a fact means something different on Windows, a Windows note follows the description.
  • min marks facts gathered even with gather_subset: [min].
